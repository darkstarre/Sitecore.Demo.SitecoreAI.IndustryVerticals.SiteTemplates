# AGENTS.md

## Cursor Cloud specific instructions

### Repository overview

This repo contains **10 independent Next.js 15 apps** under `industry-verticals/` (retail, healthcare, travel, luxury-retail, energy, vistra, orrick, interstate, littelfuse, starter). Each app is a standalone Sitecore XM Cloud front-end rendering host with its own `package.json` — there is no monorepo tooling.

### Running a site locally

1. `cd industry-verticals/<site>` (e.g. `retail`)
2. `npm install`
3. Copy `.env.remote.example` (or `.env.container.example`) → `.env.local` and set at minimum:
   - `SITECORE_EDGE_CONTEXT_ID` — **required** for content delivery
   - `NEXT_PUBLIC_DEFAULT_SITE_NAME` — site name in Sitecore (e.g. `retail`)
   - `SITECORE_EDITING_SECRET` — secures editor endpoints
4. Run `npm run dev` (this runs `sitecore-tools:build` then `next dev` + component-map watch).

**Without `SITECORE_EDGE_CONTEXT_ID`**: `sitecore-tools:build` will fail and `npm run dev` will abort. You can still start the Next.js dev server directly with `npx next dev` — the healthz endpoint (`/healthz`) works, but page routes return 500 because layout data cannot be fetched.

### Generated files (`.sitecore/`)

- `component-map.ts` and `import-map.ts` are checked in.
- `metadata.json` and `sites.json` are generated by `sitecore-tools project build` (requires Edge credentials). Without credentials, create a stub `sites.json`:
  ```json
  [{"name": "<site-name>", "hostName": "*", "language": "en"}]
  ```
  This is enough for TypeScript to compile and `next dev` to start.

### Lint / TypeScript / Test commands

All commands run from `industry-verticals/<site>`:

| Task | Command |
|------|---------|
| Lint | `npx eslint ./src/**/*.tsx ./src/**/*.ts` |
| TypeScript | `npx tsc -p tsconfig.json --noEmit` |
| Format | `npm run format` (prettier) |
| Dev server | `npm run dev` (needs Edge credentials) or `npx next dev` (partial) |
| Storybook | `npm run storybook` (port 6006) |
| Tests (vitest) | `npx vitest` (Storybook-integrated, needs browser/playwright) |

### Pre-commit hooks

Each site has a `.husky/pre-commit` hook that runs `tsc --noEmit` and `lint-staged` (prettier) from that site's directory. The `prepare` script in `package.json` sets `core.hooksPath` to the site's `.husky` directory.

### Key gotchas

- The `npm run dev` script runs `sitecore-tools:build` in serial first. If that step fails (no Edge credentials), the entire `dev` command aborts. Use `npx next dev` as a workaround for UI/component development without live content.
- `.sitecore/sites.json` is gitignored and must be generated or stubbed before TypeScript will compile.
- No lockfiles (`package-lock.json`) are committed — `npm install` will resolve fresh versions each time.
- All sites share identical project structure; fixing/changing one site's tooling typically applies to all.
